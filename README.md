# 입갤 · ipgael

**에이전트 입갤. 설명은 디시체로, 코드는 그대로.**

Codex의 설명·진행 보고·리뷰 요약을 짧고 직설적인 디시인사이드식 반말로 바꾸려는 응답 스타일 플러그인입니다.

> 현재는 README만 있는 기획 단계입니다. 플러그인 구현, 설치 방법, 실제 동작 검증은 아직 없습니다.

## 어떤 느낌인가

**일반 설명**

> PKCE는 인증 코드를 탈취한 공격자가 해당 코드를 토큰으로 교환하지 못하도록 보호하는 방식입니다.

**입갤 스타일 예시**

> PKCE는 ‘로그인 코드만 주워도 토큰은 못 받게 하는 장치’임.
> 앱이 비밀값을 하나 만들고, 처음에는 그 해시만 서버에 보내둠.
> 나중에 코드를 토큰으로 바꿀 때 원본을 내밀어서 대조하는 거임. 교환권만 주웠다고 받아가는 게 아님 ㅋㅋ

위 문장은 목표로 하는 말투를 보여주는 예시이며, 구현된 플러그인의 실행 결과는 아닙니다.

## 첫 버전에서 할 일

- Codex 세션에 공통 말투 규칙 적용
- 기술 설명, 진행 보고, 질문, 최종 리뷰까지 같은 말투 유지
- `ㅇㅋ`, `ㅋㅋ`, `~임`, `~함`과 가벼운 욕은 맥락에 맞을 때만 사용
- 단순히 말끝만 바꾸지 않고 결론과 필요한 설명부터 전달

처음부터 새 코딩 에이전트나 CLI 래퍼를 만들지는 않습니다. 긴 작업에서도 말투가 유지되는지부터 확인합니다.

## 건드리지 않는 것

- 코드, 명령어, 식별자, 오류 메시지와 직접 인용
- JSON만, 코드만, 정확한 문자열만 요구한 출력
- 커밋 메시지, PR 본문 등 별도 독자와 형식이 있는 산출물
- 도구 권한, 승인 절차, 코드 변경 범위와 실행 방식

말투가 편해진다고 사실을 지어내거나 검증하지 않은 작업을 완료했다고 보고하는 기능은 아닙니다. 욕이나 `ㅋㅋ`를 매 문장 강제로 붙이지도 않습니다.

## 지원 계획

| 대상 | 현재 상태 |
| --- | --- |
| Codex | 첫 구현 대상. 아직 미구현 |
| OMO Native | 후속 검토 대상. 연동 방식과 호환성 미확인 |
| Claude Code | 지원 미정 |

OMO Native에서 Claude 모델을 사용하는 것과 Claude Code를 사용하는 것은 다릅니다. 한쪽의 지원을 다른 쪽의 호환성으로 간주하지 않습니다.
