# 입갤 · ipgael

**에이전트 입갤. 설명은 디시체로, 코드는 그대로.**

코드 한 줄 물었는데 결재 문서가 돌아옴? 입갤 깔면 로컬 Codex가 기술 설명이든 진행 보고든 질문이든 리뷰든 결론부터 툭 던짐. 반말 어미만 갈아 끼우는 거 아님. 테스트 통과랑 배포 완료는 딱 잘라 구분하고, 코드·기술적 의미·검증 상태는 그대로 둠.

## 빠른 시작

로컬 Codex용임. 훅이 도는 환경의 `PATH`에 `node`가 있어야 함. npm 설치나 빌드부터 할 필요 없음. macOS에서 Codex `0.167.0-alpha.3.2`와 Node.js `24.15.0` 조합을 확인했음. 최소 지원 버전과 다른 OS는 아직 안 봄.

### CLI 설치

먼저 [설치 전 확인](install.md#설치-전-확인)에서 같은 이름의 마켓플레이스가 어디서 왔는지, 입갤이 이미 깔렸는지부터 봐. 공식 출처로 깔려 있으면 또 깔지 말고 그거 쓰면 됨.

1. `ipgael-local`이 없을 때만 GitHub 마켓플레이스 추가.

   ```sh
   codex plugin marketplace add JeremyDev87/ipgael --ref main --json
   ```

2. 등록 결과에 `ipgael-local`이 있는지 봐. 입갤이 아직 안 깔렸으면 그때 추가.

   ```sh
   codex plugin add ipgael@ipgael-local --json
   ```

3. `codex plugin list --marketplace ipgael-local --json`에서 설치와 활성화 상태를 각각 보고 [훅 검토](#훅-검토와-첫-실행)로 가면 됨. 깔린 거랑 켜진 건 딴 얘기임. 일부러 꺼둔 거면 그대로 둬.

### Desktop 수동 설치

1. [공식 저장소](https://github.com/JeremyDev87/ipgael)의 `main` 사본을 로컬에 받아. 이미 같은 이름으로 GitHub 마켓플레이스를 등록했다면 새로 추가하지 말고 그 출처를 계속 써.
2. 저장소를 Codex Desktop에서 로컬 프로젝트로 열고 앱 재시작. 그러면 앱이 저장소의 [마켓플레이스](.agents/plugins/marketplace.json)를 읽음.
3. **Plugins**에서 **입갤 로컬**의 **입갤 · ipgael**을 골라 설치하고 쓸 프로젝트에서 켜졌는지 봐. 이쪽은 Codex CLI 없어도 됨. [공식 로컬 설치 문서](https://developers.openai.com/plugins/build/plugins#install-a-local-plugin-manually)

### 훅 검토와 첫 실행

설치·활성화부터 확인하고 `SessionStart` 훅의 [정의](hooks/hooks.json)랑 [실행 스크립트](hooks/session-start.mjs)를 읽어봐. CLI는 `/hooks`, Desktop은 입력창의 **Review hooks** 또는 **Settings → Hooks**로 들어가면 됨. 설치했다고 바로 실행되는 거 아님. 직접 읽고 신뢰해야 훅이 돎. [공식 훅 검토 문서](https://learn.chatgpt.com/docs/hooks#review-and-trust-hooks)

새 로컬 대화에서 `Redis 캐시 만료 시간을 왜 설정해?`부터 물어봐. 다음 턴에 `그럼 만료된 뒤 요청이 오면 어떻게 돼?`도 던져보고. 마지막에 `정확히 OK만 출력해줘.` 했는데 `OK` 말고 뭐라도 더 붙으면 정확 출력 실패임.


## 사용 가이드

- 훅 신뢰했으면 새 로컬 대화 파서 평소대로 물어보면 됨. 질문마다 입갤 입갤 외칠 필요 없음.
- 이 대화에서만 끄려면 `이 대화에서 입갤 말투 꺼줘`, 다시 쓰려면 `이 대화에서 입갤 말투 다시 켜줘`. 대화 문맥에 요청이 남아 있는 동안 따르도록 안내함. 문맥 압축 뒤에도 기억하는지는 아직 안 봄.
- 계속 끄려면 **Plugins**에서 **입갤 · ipgael**을 끄고 새 대화를 열어. 기존 대화에는 이미 받은 말투 정책이 남을 수 있음. [공식 활성화 문서](https://developers.openai.com/plugins/build/plugins#how-local-marketplaces-work)

### AS-IS / TO-BE

대충 이런 차이임. 예문 복붙기가 아니라서 실제 답은 모델이랑 앞 대화에 따라 달라짐.

| 상황 | AS-IS | TO-BE |
| --- | --- | --- |
| 기술 설명 | Redis 캐시의 TTL은 저장한 값을 유효한 것으로 볼 수 있는 시간입니다. 캐시 어사이드에서는 키가 만료된 뒤 요청이 오면 앱이 원본에서 다시 읽습니다. | TTL은 캐시 유통기한임. 기한 넘긴 값을 갓 가져온 척하면 안 되잖음 ㅋㅋ 캐시 어사이드에선 만료 뒤 요청이 오면 앱이 원본에서 다시 읽음. |
| 진행 보고 | 테스트는 통과했으나 운영 배포 여부는 아직 확인하지 못했습니다. | 테스트 초록불이지 운영 초록불은 아님. 배포는 아직 확인 못 함. |
| 최종 리뷰 | `save()`가 끝나기 전에 완료 메시지를 표시합니다. 저장이 실패해도 완료로 표시될 수 있습니다. 저장 성공을 기다린 뒤 메시지를 표시하세요. 코드만 확인했으며 실행 검증은 하지 않았습니다. | DB에 쓰기도 전에 ‘저장 완료’부터 띄움 ㅋㅋ 축포부터 쏘고 경기 시작하냐. 저장 실패해도 완료로 보일 수 있으니 `await save()` 성공한 뒤에 띄워. 코드는 봤고 실행은 안 해봄. |

### 이슈 보고는 세 줄로

막힌 일 보고할 땐 뭐가 막혔는지, 어떻게 풀 건지, 이제 뭐 하면 되는지 세 줄이면 됨. 앞에 항목명이나 번호 붙이지 말고 내용부터 박아. 마지막 줄엔 지원 요청·결정·다음 행동·재발 방지 중 지금 필요한 것만. 그냥 잡담이거나 따로 정한 양식 있으면 세 줄에 억지로 욱여넣지 않음.

```text
로그인 화면은 떴는데 테스트 설정이 비어서 로그인 검증은 막힘. 화면 떴다고 로그인까지 된 거 아님.
설정 들어오면 테스트 환경에서 로그인 다시 돌릴 예정임.
반영됐다고 알려줘. 그때 내가 확인함.
```

### 정확 출력과 게시용 문구

님이 지정한 언어·말투·출력 형식이 먼저임. JSON 달랬는데 ㅋㅋ 붙이면 드립이 아니라 파서 터뜨리는 거임. 새 대화에서 이렇게 확인하면 됨.

| 요청 | 기대 출력 |
| --- | --- |
| `{"status":"ok"}`를 JSON으로만 출력해줘. | `{"status":"ok"}` |
| `console.log("OK");` 한 줄을 펜스 없이 코드만 출력해줘. | `console.log("OK");` |
| 정확히 OK만 출력해줘. | `OK` |

표의 백틱은 표시용임. 실제 답은 요청한 것만. 코드, 명령어, 로그, 식별자, 오류 메시지, 직접 인용, 제공받은 게시용 문구는 원문 그대로 두도록 안내함. 새 PR 본문이나 커밋 메시지는 읽는 사람, 저장소 규칙, 요청 형식에 맞춤. PR 초안이랑 설명을 같이 달라면 입갤체는 초안 밖 설명에만 씀. [말투 정책](policy.md)

## 문제 해결

| 증상 | 확인할 항목 |
| --- | --- |
| 마켓플레이스나 플러그인이 안 보임 | `ipgael-local`의 출처와 `ipgael@ipgael-local`의 설치 상태를 [설치 안내](install.md#설치-전-확인)에서 확인. Desktop에서 로컬 사본 쓰는 중이면 프로젝트 열고 앱 재시작. |
| 설치했는데 말투가 그대로임 | 활성화, 훅 신뢰, 훅 실행 환경의 `node`, 새 로컬 대화인지 순서대로 봐. 따로 지정한 말투나 형식이 있으면 그게 먼저임. |
| CLI에서 `plugin add`나 필요한 옵션이 지원되지 않음 | `codex --version`과 명령 도움말로 먼저 확인. 지원 안 하면 [Desktop 수동 설치](#desktop-수동-설치)로 가면 됨. |
| 훅을 다시 검토하라는 알림이 나옴 | Codex가 띄운 훅 정의랑 실행 스크립트를 다시 읽어봐. 신뢰 안 한 상태에서도 평소 Codex 작업은 계속할 수 있음. |

## 동작과 검증

[매니페스트](.codex-plugin/plugin.json)의 `SessionStart` 훅이 시작·재개·초기화·압축·분기에서 [말투 정책](policy.md)을 모델 문맥에 넣음. 정책 파일에 문제가 있으면 훅은 아무것도 안 뱉고 끝남. 훅이 떴다고 말투까지 먹혔다는 뜻은 아님. 말투랑 정확 출력은 실제 답으로 봐야 함. 도구 호출·권한·승인 설정은 기존 Codex 정책 그대로.

- **확인함:** `node --test tests/session-start.test.mjs`로 훅 전달·파일 오류 처리를 검사함. 격리된 macOS Codex 호스트에서 로컬 설치, 훅 발견, 시작·재개·초기화·압축·분기 전달, 미신뢰·비활성 상태, 테스트 응답 전달이랑 승인 흐름까지 확인했음.
- **아직 안 봄:** Desktop에서 처음부터 끝까지 클릭으로 설치하는 흐름, 실제 모델의 말투·정확 출력·대화별 끄기는 실사용 확인이 남아 있음. 이 안내 범위는 로컬 Codex까지.
